# Обсуждение DeploymentRequested

**Согласовано.** Рецензенты — Полина и Влад. Связанная задача [#2](https://github.com/project-cloud-switch/CloudSwitch/issues/2).

## Исходный пробел

API и Doctor публикуют одинаковый запрос. Предыдущая спецификация содержала только имя, образ, окружение и провайдера. Этого было недостаточно для согласованной миграции и автономного восстановления без обращения к отказавшему источнику.

## Согласованные решения

1. **Причина запуска и отслеживание инцидента**
   - В `DeploymentRequested` добавлен `DeploymentTrigger` (`Manual`, `Automatic`).
   - Для автоматического восстановления добавлен `IncidentId` (`Guid?`), обеспечивающий дедупликацию в БД и при выполнении по `(DeploymentId, IncidentId)`.

2. **Содержимое неизменяемого снимка `DeploymentSpecification`**
   - Контейнер и реестр — `ContainerPort` с умолчанием 80, `ImagePullSecretReference` со ссылкой на токен реестра в Vault, закреплённый образ с digest или тегом.
   - Ресурсы — `CpuCores` с умолчанием 1.0 и `MemoryMb` с умолчанием 512.
   - Конфигурация и секреты — словарь несекретных `Env` и словарь `SecretReferences` со ссылками Vault (`vault://path#key`). Значения секретов исключены из сообщений брокера и сохраняемых логов.
   - Инфраструктура и выполнение — `TargetConfigurationId` со ссылкой на профиль PostgreSQL и одобренное имя и версия/ревизия `TerraformModule`.
   - Проверка и переключение — `HealthCheck` (`HealthCheckPolicy`) до переключения, `EntrypointDomain` и `TrafficRoutingProvider`.

3. **Гарантия автономности**
   - Worker создаёт инфраструктуру и выполняет проверки независимо от источника, используя снимок. Обращения к отказавшему исходному облаку во время выполнения запрещены.

4. **Состояние реализации**
   - C#-контракты `CloudSwitch.Contracts` и модульные тесты `CloudSwitch.Contracts.Tests` реализованы и проверены.
