# Обсуждения готовности контрактов

Согласованные обсуждения [запроса развёртывания](deployment-request.md) и [прогресса задания](job-progress.md) определяют общие контракты сообщений. [Решения по реализации API v1](../decisions/api-v1.md) описывают владение схемой и интеграцию. Остальные заметки сохраняют открытые вопросы для рассмотрения.

Цель — согласовать небольшой базовый набор контрактов, который API, Worker и Notifications смогут реализовать независимо. Каждое обсуждение содержит собственный статус согласования.

Перед встречей прочитайте [архитектуру](../architecture.md), [текущие контракты](../contracts.md) и [доменную модель](../domain-model.md).

| Тема | Необходимое решение | Предлагаемые ведущие |
| --- | --- | --- |
| [Запрос развёртывания](deployment-request.md) | Общие поля ручного и автоматического запроса, содержимое снимка. | Полина и Влад |
| [Прогресс задания](job-progress.md) | Фазы, критерии завершения и данные ошибки. | Влад и Степан |
| [Конфигурация Doctor](doctor-configuration.md) | Состав обновления и начальный механизм доставки и перезапуска. | Полина и Влад |
| [Поведение контрактов](contract-behavior.md) | Валидация, инциденты, дубликаты, повторы и продолжение выполнения. | Влад и Степан |
| [Общее хранение](shared-persistence.md) | Таблицы, границы записи и процесс миграций. | Полина, Влад и Егор |
| [Выпуск базовой версии](contract-release.md) | Ревью, тесты, согласованность задач и готовность к слиянию. | Все |

## Предлагаемый план встречи

Участники — Полина, Влад, Степан и Егор. Продолжительность 45 минут.

1. Запрос развёртывания — 10 минут.
2. Прогресс задания — 10 минут.
3. Конфигурация Doctor — 10 минут. Будущее масштабирование реплик рассмотреть отдельно, если оно мешает простому начальному решению.
4. Поведение и хранение — 10 минут.
5. Фиксация решений, ответственных и следующих задач — 5 минут.

Для каждой темы запишите **решение, ответственного и оставшееся действие** в соответствующей заметке. Затем согласованно обновите контракты, документацию и затронутые задачи GitHub. Результатом встречи должен стать реализуемый базовый вариант.
